# v7.6 upgrade — validation and limits

## Changes and evidence

- **105 automated tests passed** after the iframe matching change, including repeated-agent-failure classification, task deadline versus inner timeout, provider failure codes with no raw payloads, proxy configuration rollback, encrypted-settings corruption and missing-key behavior, and restoring the database with its encryption key and encrypted settings.
- The pinned Browser-use agent and real Chromium completed a deterministic two-step task with DOM and vision input, Unicode entry, and simultaneous JPEG frames. The owned Chromium process-loss test preserved its checkpoint and completed after explicit resume. This does not measure a live model's reasoning quality.
- Controlled local widget tests covered a single checkbox click, vision-model action flow, no event flood, and manual takeover. Google's official public reCAPTCHA test key passed after an OOPIF matching repair: a visible iframe with an empty CDP target URL is checked against its actual location, and duplicate target sessions are deduplicated. Google's test key always passes; this does not prove production CAPTCHA solving.
- Chromium editor tests repaired a textarea and observed the fixture's own PASS result. Integrity-checked real Monaco 0.52.2, Ace 1.43.3 and CodeMirror 5.65.20 tested reading, writing and read-only behavior; Monaco also tested container selection and ambiguity. Other versions and websites are not guaranteed.
- A separate Browser-use 0.13.14 no-dependency preflight passed 26 selected tests, controlled editor integration and browser loss/resume against the existing dependency set. Its dependency requirements differ from production; this is not a fully resolved upgrade or speed comparison. The application remains on 0.13.11.
- Authenticated Chromium-through-proxy testing used a controlled local HTTP proxy; separate tests cover HTTP(S), SOCKS4a, SOCKS5, fail-closed routing and save failures. The owner's Webshare endpoints did not produce a successful result in the earlier environment. The in-app exit IP test checks the browser only, not a packet-level leak audit or every model provider.
- Chromium mobile viewport tests covered 360/390/430/768/1280 widths, simulated keyboard layout, scroll anchoring, draft restoration, transport disconnect, expired session sign-in, encrypted-settings error display, reduced motion and accessibility labels. Screenshot files are explicitly labeled test content; no physical iPhone/Safari check was performed.
- The normal local `serve.py` entrypoint reached readiness, returned 404 for QA-only routes, opened a real 1280px Chromium frame at mobile widths with no JavaScript errors or horizontal overflow, and completed shutdown. This was a local source run, not a Railway or production-container deployment.
- A revised-timer 60-second controlled QA run passed with 10 steps, 40 frames per viewer, a simulated provider fault and explicit resume after restart. It used an empty QA container with host-mounted Python and Chromium dependencies under a 2 GiB/one CPU cgroup; it is not a production Docker image test. Report: `validation/soak-upgrade-60s.json`.
- The test harness now starts the duration after the task reaches running state. It supports a fully local labeled fixture for environments where browser egress is unavailable; that option does not validate external navigation or proxy egress. The earlier production-image 7203.7-second run in `validation/soak-2g-7200s.json` includes setup and a deliberate restart, uses deterministic inference, and does not establish 7200 uninterrupted seconds of active execution.
- Raw Browser-use, event-bus and CDP logs can contain page or provider content; their loggers are suppressed and the application reports bounded status codes. A controlled repeated-failure integration verified the app state and emitted output did not expose the fixture error. This is not a guarantee that arbitrary server or infrastructure logs contain no sensitive information.

## Not verified

No physical iPhone/Safari, current live model account, successful Webshare endpoint, new Railway deployment, or complete packet-level DNS/WebRTC/fingerprint isolation was verified in this environment. The owner stopped the revised long endurance run before completion; no pass is claimed for it. The earlier historical report remains separately labeled. The published Dockerfile was not rebuilt as a production image for this revision: the earlier reference image was 1.54 GB, while the current source package is substantially smaller.

The app retains one task, one browser and explicit resume after server restart. Local Compose uses 2 GiB and one CPU; Railway resource limits and billing depend on its current plan and settings.
